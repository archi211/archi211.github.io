# PocketOption → MetaTrader 5: мост M1, протокол 2

Новые `server.py` и `Free_OTC.mq5` работают **вместе**. Советник предназначен
для PocketOption; режим Binodex из старого советника сюда не перенесён.
Это не официальный API PocketOption и не гарантия непрерывной работы сервиса.
Используйте доступ к данным в пределах разрешений и правил брокера.

## Что изменено

- Один управляющий цикл соединения; закрытие сокета и завершение фоновых задач
  перед повтором. Экспоненциальная задержка с небольшим случайным разбросом;
  после HTTP 401/403/429 при подключении к брокеру — пауза пять минут, без смены IP.
- TLS-сертификаты проверяются. Отдельно обслуживаются WebSocket ping/pong,
  Engine.IO ping/pong и прикладной heartbeat `ps`.
- SSID читается из файла, не передаётся по HTTP и не попадает в логи.
  Подтверждённый отказ авторизации переводит мост в `AUTH_REQUIRED` до изменения
  файла. Сетевой тайм-аут не объявляется «мёртвым токеном».
- Все тики пакета обрабатываются без подмены `json.loads`. Запоздавшие и
  невалидные данные отбрасываются. Свежесть контролируется отдельно по парам.
- История хранится между переподключениями и сохраняется атомарно в локальный
  кэш каждые 30 секунд, при разрыве и при корректном завершении. Кэш после
  запуска никогда не считается свежими котировками.
- Советник запрашивает полную **доступную** историю после изменения `run_id`
  или `epoch`, проверяет импорт и не создаёт искусственных тиков. Чужие
  индикаторы, графики и накопленная история не удаляются.
- Flask обслуживается через Waitress, без веб-панели изменения секретов.

## Важные ограничения данных

Мост использует небольшой read-only WebSocket-адаптер вместо архивированной
`pocketoptionapi-async`. Зависимости старой библиотеки, NumPy, pandas и Selenium
ему не нужны. Формат `changeSymbol`, авторизации и котировок взят из публичного
[клиента ChipaDevTeam](https://github.com/ChipaDevTeam/PocketOptionAPI), а бинарные
события реализованы согласно [Socket.IO](https://socket.io/docs/v4/socket-io-protocol/).

История запрашивается **последовательно**, с интервалом не менее
`request_spacing` между запросами и не чаще `history_interval` для каждой пары.
Дополнительно используются поступающие тики для уточнения уже существующей
M1-свечи. **Это не гарантированная одновременная подписка на тики всех пар**:
сервер брокера может переключать поток при `changeSymbol`. Новая свеча не
изобретается из одного позднего тика; её OHLC сначала должен прийти в истории.

Поддерживаются JSON-события `42[...]`, бинарные JSON-вложения Socket.IO,
пакеты тиков `[[symbol, unix_seconds, price], ...]` и история с явными полями
`asset`, `period: 60`, `candles`/`data`/`history`. Свечи-массивы от брокера имеют
порядок `[time, open, close, high, low]`, объектные свечи — именованные OHLC-поля.
В HTTP используется `[utc_milliseconds, open, high, low, close]`.
Время начала свечи должно быть выровнено по минуте.

Ответ без инструмента или периода не привязывается «наугад» к текущему запросу.
Изменение протокола брокера может потребовать адаптации. В этом случае лучше
явный `HISTORY_TIMEOUT`/`STALE`, чем свечи другой пары под правильным названием.

`changeSymbol` не гарантирует выдачу 3000 свечей и не имеет подтверждённой здесь
пагинации. Мост хранит до 3000 **полученных** баров по паре, не заполняет
отсутствующие минуты выдуманными ценами и возвращает `history_complete: false`.
После длительного простоя история восстанавливается только в пределах данных,
реально присланных брокером или сохранённых в кэше. Таймер MT5 не ускоряет
получение данных самим Python-сервером.

## Установка на Windows

Сначала остановите старый сервер и сохраните резервную копию обоих старых
скриптов. Не устанавливайте это поверх старого окружения с тремя вариантами
API-библиотеки. Используйте отдельную папку, например `D:\PocketOptionBridge`.

Скопируйте туда `server.py`, `requirements.txt`, `bridge.example.json` и
`pairs.example.json`. Рекомендуется Python **3.12 x64**; код требует Python 3.11+.

В PowerShell:

```powershell
Set-Location D:\PocketOptionBridge
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item bridge.example.json bridge.json
Copy-Item pairs.example.json pairs.json
notepad ssid.txt
```

В `ssid.txt` сохраните **полный действующий пакет авторизации** вашего аккаунта:
`42["auth",{...}]`, без Markdown, внешних кавычек и пояснений. Не присылайте
этот файл в чат и не добавляйте его в Git. Сервер берёт `isDemo` из пакета,
а не меняет тип аккаунта самостоятельно. По умолчанию используется европейский
endpoint для соответствующего типа аккаунта.

Список пар редактируется в `pairs.json`. Начните с трёх пар из примера.
Имя должно заканчиваться на `_otc` (регистр суффикса не важен); до суффикса
допускается до 20 латинских букв, цифр и знаков `_`, `#`, `.`, `-`.
`digits` задаёт точность пользовательского символа MT5: проверьте её по данным
брокера; значения по умолчанию не являются универсальными для всех инструментов.
При добавлении большого числа пар увеличится время полного обхода. Настройте
сроки свежести согласно допустимой задержке, а не просто ради зелёного статуса.
Ограничитель запросов — локальная предосторожность, не официальная квота брокера.

Запуск:

```powershell
.\.venv\Scripts\python.exe server.py
```

Остановка: `Ctrl+C`. При смене содержимого `ssid.txt` сервер переподключается
сам; для изменения `bridge.json`, `pairs.json`, `api_token.txt` требуется
перезапуск. Секреты лучше обновлять заменой временного файла, чтобы сервер
не увидел наполовину записанный пакет. После проверки сохраните локальный
снимок зависимостей: `python -m pip freeze > requirements.local.lock.txt`.

## Установка советника

1. Скопируйте `Free_OTC.mq5` в `MQL5\Experts\PocketOptionBridge` вашего терминала.
   JSON-парсер встроен в советник; дополнительных `.mqh` не требуется.
2. Скомпилируйте `Free_OTC.mq5` в MetaEditor. Старый `JAson.mqh` не требуется.
3. В MT5: «Сервис → Настройки → Советники → Разрешить WebRequest для следующих
   URL» добавьте `http://127.0.0.1:5000`.
4. Запустите Python-сервер и прикрепите новый советник к одному обычному
   графику. Не запускайте параллельно старый советник для тех же custom symbols.
5. Оставьте `InpServerUrl = http://127.0.0.1:5000`. Если включили HTTP-токен, укажите тот же
   токен во входном параметре советника `InpApiToken`.
6. Откройте созданные инструменты с суффиксом `_OTCpo` в «Обзоре рынка».

Если инструмент уже создан старым советником с другой точностью, новый
советник сообщит `Digits mismatch` и не станет менять точность с риском потери
истории. Согласуйте `digits` в `pairs.json` с существующим инструментом либо
сначала экспортируйте историю и отдельно выполните миграцию custom symbol.

Советник работает только как импортёр OHLC, не выставляет торговые заявки.
Используется `CustomRatesUpdate`; Bid/Ask и тиковая история не имитируются.
Роботы, зависящие от `OnTick`, из этого моста полноценный поток тиков не получат.
`WebRequest` синхронный: один медленный запрос может задержать один проход
таймера, но не запускается пакет запросов по всем инструментам одновременно.

## VPN, удалённый доступ и BAS

- sing-box/VLESS/Hysteria2 настраиваются и запускаются **отдельно**. Код не
  скачивает подписки, не меняет системные маршруты, не завершает чужие процессы
  и не вращает IP. Перед запуском отдельно проверьте конфигурацию вашей версии
  sing-box и журнал туннеля. Смена сети вызывает обычное восстановление сокета.
- Если MT5 и Python на одном компьютере, ngrok не нужен. По умолчанию сервер
  слушает только loopback. Для удалённого доступа создайте случайный API-токен
  минимум 32 символа в `api_token.txt`, задайте его в советнике и используйте
  HTTPS/защищённую сеть. При прослушивании не-loopback без такого токена сервер
  не запустится. Публикация loopback через ngrok тоже требует токена, даже если
  сам сервер не может определить наличие туннеля.
- Получить токен локально можно командой
  `python -c "import secrets; print(secrets.token_urlsafe(32))"`.
  Этот токен для HTTP-моста, **не SSID брокера**. Не передавайте его в URL.
- При `bas_trigger: true` сервер создаёт `need_auth.trigger` при отсутствии
  корректного SSID или явном отказе авторизации. BAS должен получить новый
  SSID разрешённым способом, атомарно заменить `ssid.txt` и удалить trigger.
  Одно удаление trigger не считается успешной авторизацией. Через
  `auth_wait_timeout` сервер пишет предупреждение и остаётся офлайн, проверяя
  файл; бесконечной блокировки event loop или попыток входа нет.
- Ограничьте ACL файлов секретов вашей учётной записью Windows. Старую
  VPN-подписку, ранее попавшую в переписку/публичный доступ, перевыпустите.

## HTTP и диагностика

Все маршруты при наличии `api_token.txt` требуют `Authorization: Bearer TOKEN`.

| Маршрут | Назначение |
| --- | --- |
| `/v1/pairs` | Настроенные пары, включая ещё не загруженные, и их статусы |
| `/v1/klines?symbol=EURUSD_otc&limit=3000` | Доступная история M1 |
| `/v1/klines?symbol=EURUSD_otc&limit=3000&since=...` | Бары с UTC timestamp **не меньше** `since` в миллисекундах |
| `/healthz`, `/server_status` | Жив ли рабочий поток, состояния пар; 503 при остановке потока |
| `/readyz` | 200 только если все настроенные пары `LIVE`, иначе 503 |

HTTP 200 с `pair_status: STALE` — это доступный кэш, **не свежая котировка**.
`run_id` меняется при запуске процесса, `epoch` — при успешной авторизации нового
соединения. `LOADING` не означает «активна»: история ещё не получена.
Пара с тайм-аутом остаётся в списке и опрашивается реже; не объявляется
«недоступной у брокера» по локальному списку старой библиотеки.

В `bridge.log` записываются состояния, имена инструментов, классы ошибок и
HTTP-коды без содержимого auth-пакетов. Журнал ротируется (5 резервных файлов
по 2 МБ). Не включайте WebSocket DEBUG на настоящем аккаунте: там могут быть
секреты. Ошибки сети/импорта советника смотрите в «Эксперты» MT5.

## Проверка перед длительной эксплуатацией

Из этой папки в окружении с `requirements.txt`:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe tests\check_mql_contract.py
```

Автотесты используют синтетические данные и локальный WebSocket-сервер,
не подключаются к брокеру. Они не заменяют проверку актуального протокола
PocketOption, компиляцию MetaEditor и реальную работу Windows/sing-box/MT5.

На демо-аккаунте проверьте: загрузку трёх пар и совпадение OHLC с брокером;
отключение сети и возврат без перезапуска; истечение SSID и замену файла;
смену `epoch` с реальным повторным запросом истории в MT5; перезапуск Python
с сохранением кэша; одну отсутствующую пару без остановки остальных. Затем
увеличивайте число пар и проведите 24–72-часовой прогон, проверяя задержки,
пропуски свечей, память и восстановление. История с пробелами должна оставаться
явно неполной, а не «исправляться» синтетическими барами.
